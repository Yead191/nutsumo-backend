====================================================================================================
               NUTSUMO SERVICE MARKETPLACE - JOB POST TO BOOKING WORKFLOW GUIDE
====================================================================================================

Target: Frontend Web Developers (Customer, Artisan & Admin Dashboard Pages)
Base URL: http://localhost:5000/api/v1 (or your production API URL)
Auth Headers: Authorization: Bearer <ACCESS_TOKEN>

----------------------------------------------------------------------------------------------------
1. PROJECT OVERVIEW & LIFECYCLE ARCHITECTURE
----------------------------------------------------------------------------------------------------
Nutsumo connects Customers (Service Seekers) with Verified Artisans / Pros (Service Providers).
The core monetization and workflow lifecycle transitions from a Job Request to a Confirmed Booking:

  [Customer Posts Job] 
         │ (Status: OPEN)
         ▼
  [Automated Matching Engine]
         │ (Matches Category/Service & Location -> Emits Kafka Event)
         ▼
  [Real-Time Notifications & Emails to Matched Artisans]
         ▼
  [Artisan Views Job & Submits Quotation / Proposal]
         │ (Quotation Status: PENDING)
         ▼
  [Customer Receives Quotation -> Reviews All Proposals]
         ▼
  [Customer Accepts Best Quotation] ──(ATOMIC MONGODB TRANSACTION)──┐
         │                                                          │
         ├─► Selected Quotation: ACCEPTED                           │
         ├─► Job Status: BOOKED                                     │
         ├─► All Other Pending Quotations: REJECTED (with reason)   │
         ├─► New Booking Created: CONFIRMED (Booking #BK-XXXX-XXXX) │
         └─► Kafka Events, Sockets & Email Confirmations Dispatched ─┘
         ▼
  [Confirmed Booking Details Screen / Chat / Execution]

Key Status Enums:
  - Job Status: 'OPEN' | 'BOOKED' | 'IN_PROGRESS' | 'COMPLETED' | 'CANCELLED'
  - Quotation Status: 'PENDING' | 'ACCEPTED' | 'REJECTED' | 'WITHDRAWN'
  - Rate Type: 'HOURLY' | 'DAILY' | 'FIXED'
  - Booking Status: 'CONFIRMED' | 'IN_PROGRESS' | 'COMPLETED' | 'CANCELLED'
  - Payment Status: 'UNPAID' | 'PAID' | 'REFUNDED'


====================================================================================================
2. BUSINESS LOGIC & CONSTRAINTS (MUST-KNOW FOR FRONTEND)
====================================================================================================
1. Verified Artisan Guard:
   - Only artisans with `role === 'ARTISAN'`, `status === 'active'`, and `identityStatus === 'verified'`
     can submit quotations. Non-verified artisans receive 403 Forbidden. Frontend should show a verification badge/prompt.
2. Self-Quotation Guard:
   - A customer cannot submit a quotation to their own job.
3. Open Job Constraint:
   - Quotations can ONLY be submitted, updated, or accepted while `job.status === 'OPEN'`.
4. Unique Active Quotation Rule (Compound Index `{ job: 1, artisan: 1 }`):
   - One artisan can only have one active quotation per job.
   - If PENDING: Frontend must route the artisan to Edit/Update proposal instead of submitting a new one.
   - If REJECTED / ACCEPTED: Artisan cannot re-submit.
   - If WITHDRAWN: Submitting a new quotation re-activates the existing record to PENDING with new pricing.
5. Atomic Acceptance:
   - When Customer clicks "Accept Offer", backend performs an atomic MongoDB transaction.
   - The selected quote is ACCEPTED, Job becomes BOOKED, Booking is created, and all rival quotes are REJECTED.

PAGE 3.1: Post a Job / Request Service ("/account/post-job")
----------------------------------------------------------------------------------------------------
Purpose: Customer creates a new job post with location, budget, preferred date, and optional images.
Method: POST
Endpoint: /api/v1/job
Access: Customer (auth header required)
Content-Type: multipart/form-data (or application/json if no images)

Form-Data Fields:
  - title: string (min 3, max 150)
  - description: string (min 10, max 5000)
  - category: string (MongoDB ObjectId of Category, optional if custom)
  - service: string (MongoDB ObjectId of Service, optional if custom)
  - customServiceName: string (optional, if custom service typed)
  - location: string (e.g. "Banani, Dhaka" or "Brooklyn, NY")
  - postCode: string (e.g. "1213" or "10001")
  - budget: number (e.g. 150)
  - preferredDate: string ISO (e.g. "2026-11-15T10:00:00.000Z")
  - images: binary files (Max 10 images)
  * Note: You can send fields individually in FormData OR as a JSON string inside `data` field + files under `images`.

6. REAL-TIME NOTIFICATIONS & WEBSOCKET GUIDE
====================================================================================================

The backend emits Socket.io events and dispatches Kafka background events on every stage of the flow:

1. When a new Job is created:
   - Kafka event: `JOB_CREATED` -> Dispatches batch notifications to matching active artisans.
   - Socket event: `getNotification::<artisanUserId>`
   - Payload:
     {
       "title": "New job available",
       "message": "A new job \"Fix Leaking Kitchen Sink\" matches your service.",
       "path": "/jobs/6ae5587b45c428cac7e80f79",
       "seen": false
     }

2. When Artisan submits a Quotation:
   - Socket event: `getNotification::<customerUserId>`
   - Payload:
     {
       "title": "New Quotation Received",
       "message": "Rahim Plumbing Solutions submitted an offer of $140 (FIXED) for \"Fix Leaking Kitchen Sink\".",
       "path": "/jobs/6ae5587b45c428cac7e80f79"
     }
   - Automated HTML Email sent to Customer with "Review Proposal" button.

3. When Customer Accepts Quotation:
   - Socket event to Selected Artisan: `getNotification::<acceptedArtisanId>`
     Title: "Quotation Accepted! 🎉"
     Message: "Great news! Your quotation for \"Fix Leaking Kitchen Sink\" has been accepted. Booking #BK-428812-7814 is confirmed."
     Path: "/bookings/6ae591144ed4c1e730b88f99"
   - Socket event to Rejected Artisans: `getNotification::<otherArtisanId>`
     Title: "Quotation Update"
     Message: "The customer has selected another proposal for \"Fix Leaking Kitchen Sink\"."
   - Automated HTML Confirmation Emails sent to both Customer and Artisan.

Notification API Endpoints for Frontend:
  - GET /api/v1/notification (Fetch unread/all notifications with pagination)
  - PATCH /api/v1/notification/:id (Mark single notification as seen)
  - PATCH /api/v1/notification/read-all (Mark all as seen)
  - DELETE /api/v1/notification (Clear all notifications)

7. RECOMMENDED REDUX RTK-QUERY SERVICE SLICE (FRONTEND BOILERPLATE)
====================================================================================================

```typescript
// quotationApi.ts
import { baseApi } from '@/redux/api/baseApi';

export const quotationApi = baseApi.injectEndpoints({
  endpoints: (builder) => ({
    // Artisan: Submit Quotation
    submitQuotation: builder.mutation({
      query: (body) => ({
        url: '/quotations',
        method: 'POST',
        body,
      }),
      invalidatesTags: ['Quotations', 'Jobs'],
    }),

    // Artisan: Get My Submitted Proposals
    getMyQuotations: builder.query({
      query: (params) => ({
        url: '/quotations/my-quotations',
        method: 'GET',
        params,
      }),
      providesTags: ['Quotations'],
    }),

    // Customer: Get Proposals for a Job
    getJobQuotations: builder.query({
      query: (jobId) => ({
        url: `/quotations/job/${jobId}`,
        method: 'GET',
      }),
      providesTags: (result, error, jobId) => [{ type: 'JobQuotations', id: jobId }],
    }),

    // Customer: Accept Proposal
    acceptQuotation: builder.mutation({
      query: (quotationId) => ({
        url: `/quotations/${quotationId}/accept`,
        method: 'PATCH',
      }),
      invalidatesTags: ['JobQuotations', 'Quotations', 'Jobs', 'Bookings'],
    }),

    // Customer: Reject Proposal
    rejectQuotation: builder.mutation({
      query: ({ quotationId, rejectReason }) => ({
        url: `/quotations/${quotationId}/reject`,
        method: 'PATCH',
        body: { rejectReason },
      }),
      invalidatesTags: ['JobQuotations', 'Quotations'],
    }),

    // Artisan: Edit Proposal
    updateQuotation: builder.mutation({
      query: ({ id, ...body }) => ({
        url: `/quotations/${id}`,
        method: 'PATCH',
        body,
      }),
      invalidatesTags: ['Quotations', 'JobQuotations'],
    }),

    // Artisan: Withdraw Proposal
    withdrawQuotation: builder.mutation({
      query: (id) => ({
        url: `/quotations/${id}/withdraw`,
        method: 'PATCH',
      }),
      invalidatesTags: ['Quotations', 'JobQuotations'],
    }),

    // Get My Bookings (Customer or Artisan)
    getMyBookings: builder.query({
      query: (params) => ({
        url: '/bookings/my-bookings',
        method: 'GET',
        params,
      }),
      providesTags: ['Bookings'],
    }),
  }),
});

export const {
  useSubmitQuotationMutation,
  useGetMyQuotationsQuery,
  useGetJobQuotationsQuery,
  useAcceptQuotationMutation,
  useRejectQuotationMutation,
  useUpdateQuotationMutation,
  useWithdrawQuotationMutation,
  useGetMyBookingsQuery,
} = quotationApi;
```
